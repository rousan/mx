The problem

Switching features costs you 20 minutes

You're deep in a feature. An urgent bug lands. Then the tax kicks in:

git stash
checkout + branch
reinstall deps
port clash
rebuild context

And a coding agent can only work one checkout at a time — so running several agents in parallel is off the table entirely.

The idea

Give every feature its own desk

Its own folder, branch, ports, and coding-agent session — that stays exactly as you left it.

Built on native git worktrees, so there's no second copy of the repo and no stashing. Switching between features becomes a swipe, not a 20-minute reset.

On disk

The whole runtime is one folder

~/mx/ the runtime — one folder ├── repos/ pristine clones (read-only) │ ├── muze-ai/git │ └── scaligent/git ├── works/ one folder per feature │ └── project-hummingbird/ │ ├── wt/scaligent/ the worktree you code in │ ├── sessions/ session summaries │ └── work.json manifest (mx-owned) ├── context/ shared memory · INDEX.json ├── hooks/ lifecycle hook hub ├── bin/ runtime-wide CLI helpers └── files/ shared operational values

mx owns the structure — work.json, the editor workspace, and ports are written only through mx commands. repos/ stay read-only; everything you build lives in works/<feature>/wt/.

The moment a worktree exists, mx fires the post-worktree-create hook — you decide what “ready” means (copy env, install, seed, …), in any language. It's one hub of lifecycle hooks: worktree create/remove, work archive/unarchive, repo fetch, health, and session-prompt.

Memory & lifecycle

Pause a feature, pick it up later

Active
Worktrees, ports, an agent session — and sessions/*.md notes as you go.
→mx work archive
Archived
Worktrees & ports freed. Branches and session summaries kept — recoverable.
→mx work unarchive
Back to work
Worktrees re-created; continue right where you left off.

Every work keeps session summaries (sessions/*.md) — a distilled record of each session, so you or a fresh agent can resume cold. Done for now? mx work archive frees the ports and worktrees but keeps the branches and notes; mx work unarchive brings it all back.

Why not roll your own?

"Can't I just use subagents, or a tab per feature?"

Subagents in one session · or a terminal tab per feature
  • You wire up git worktree by hand — and clean it up by hand
  • Ports are your problem: pick them, track them, dodge clashes
  • No lifecycle — nothing to archive, recover, or tear down cleanly
  • Every session starts cold; no memory shared between features
  • Tabs, folders, and branches pile into clutter you hold in your head
With mx — it's managed
  • One command: the work, its worktrees, branches, and workspace
  • Ports allocated & tracked, unique across the whole runtime
  • mx work archive / unarchive — a recoverable lifecycle
  • A runtime context registry every agent reads from
  • Mission Control board — the whole fleet at a glance

Subagents and worktrees are the primitives. mx is the manager around them — works, ports, repos, lifecycle, and shared context — so parallelism stays organized instead of turning into clutter.
